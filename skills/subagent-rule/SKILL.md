# subagent-rule

親 agent と子 subagent のあいだで作業を分割し、agent 間のやり取りをリポジトリの `comm-agent/` に残すための基礎ルール。agent 間の依頼と報告は必ずフォーマットで行い、ファイルとして追跡可能にする。

このドキュメントは**自己完結**している。分割の条件、依頼・報告のフォーマット、`comm-agent/` の運用の定義はここだけに置く。

## 分割の条件

次を**両方**満たすときだけ、subagent へ作業を分割する。

- 作業単位について**入力と完了条件が明示されている**。成果目標と責任範囲を 2 文程度で書き切れる状態である。
- 作業単位どうしの**書き込み対象（ファイル・ディレクトリ・リソース）が重複しない**。

どちらか一方でも満たさない場合は分割しない。入力が未確定なら入力を確定させてから再挑戦し、書き込み対象が重なるなら作業単位を締め直す。

## 使いどころ

- 複数ファイルの調査（ファイルやモジュールごとに作業単位を割る）
- issue に対する観点別レビュー（観点ごとに作業単位を割る）
- 独立した実装作業（書き込み先が交差しない場合）

作業単位が 1 つしかない場合、入力が未確定な場合は使わない。

## 管理ディレクトリ

- 管理場所: リポジトリ直下の `comm-agent/`。GitHub Issues や外部のメッセージングは使わない。
- サブディレクトリは作らない（採番と一覧性が崩れるため）。
- ファイルは**削除・改名・移動しない**。既存ファイルを上書きせず、追記のみ行う。

### ファイル名の命名規則

- 形式: `comm-agent/NNNN-<unit-slug>.md`
  - `NNNN`: 対象 issue の 4 桁ゼロ埋めの番号。`issues/NNNN-<slug>.md` の番号と一致させる。
  - `<unit-slug>`: 作業単位を表す英小文字・数字・ハイフンの短い名前（30 文字程度）。
  - 例: `comm-agent/0006-search-measure.md`
- 同じ issue に複数の作業単位がある場合は `<unit-slug>` で区別する（`comm-agent/0006-search-measure.md` と `comm-agent/0006-search-review.md`）。
- 番号は新規に採番しない。対象 issue の番号を使い、`<unit-slug>` が同じ issue 内で重複しないように付ける。
- 1 作業単位 = 1 ファイル。依頼（親 -> 子）と報告（子 -> 親）は同じファイルにこの順で追記する。追跡可能性を保つため、依頼と報告を別ファイルに分けない。

## 委任ファイルのテンプレート

1 作業単位 = 1 ファイルへ、依頼と報告を見出し順で追記する。`{...}` は実際の値に置き換えて、**見出し構成を変えない**。報告は subagent が稼働してから追記し、稼働前は「未実行」のままにする。

```markdown
# {NNNN}: {作業単位のタイトル}

対象 issue: {#NNNN}

## 依頼（親 -> 子 subagent）

成果目標: {達成すべき成果の状態。手順ではなく結果状態で 2 文程度}
責任範囲: {書き込みを許可されるファイル / ディレクトリ / リソース}(範囲外への書き込みは禁止)
入力: {提供するコンテキスト・制約・関連成果物の全文またはパス}
完了条件: {subagent 自身で検証可能な条件}
成果物: {出力先ファイル / ディレクトリのパス、または報告本文の送り先}
報告指示: 実行中に新たな依存・競合・範囲外の問題を見つけた場合は、その作業を中断して親に報告する

## 報告（子 subagent -> 親）

未実行
```

## 依頼フォーマットの項目

| 項目 | 書くこと |
| --- | --- |
| `成果目標` | 達成すべき成果の状態。手順ではなく結果状態で 2 文程度で記述する |
| `責任範囲` | 書き込みを許可されるファイル / ディレクトリ / リソース。範囲外への書き込みは禁止される |
| `入力` | 提供するコンテキスト・制約・関連成果物の全文またはパス |
| `完了条件` | subagent 自身が自分の判断で検証できる条件（実行するコマンドや確認項目で書ける形にする） |
| `成果物` | 出力先ファイル / ディレクトリのパス、または報告本文の送り先 |
| `報告指示` | 新たな依存・競合・範囲外の問題を見つけた場合はその作業を中断して親に報告する旨 |

## 報告フォーマットの項目

報告は依頼と同じファイルの「報告（子 subagent -> 親）」見出しの下に追記する。

```text
状態: <完了 / 一部完了 / ブロック のいずれか 1 つ>
成果: <成果目標に対して達成した結果>
成果物: <出力したファイルパスの一覧、または出力先>
完了条件判定: <完了条件ごとに充足/未充足と理由>
新規依存・阻害要因: <見つかった問題と、その扱いの提案（追加入力など）>
次の行動: <親が決定・実行すべきこと>
```

| 項目 | 書くこと |
| --- | --- |
| `状態` | `完了` / `一部完了` / `ブロック` のいずれか 1 つ |
| `成果` | 成果目標に対して達成した結果 |
| `成果物` | 出力したファイルパスの一覧、または出力先 |
| `完了条件判定` | 完了条件ごとに充足 / 未充足と、その理由 |
| `新規依存・阻害要因` | 見つかった問題と、その扱いの提案（追加入力など） |
| `次の行動` | 親が決定・実行すべきこと |

## 書き込み排他

- 同一ファイルへの重複編集は禁止する。作業単位どうしの責任範囲が重ならないように切り出す。
- 責任範囲が重ならない場合は、同じファイルへは 1 つの作業単位だけが書き込む。
- 責任範囲外へ書き込みが必要になっても書き込まない。報告フォーマットの `新規依存・阻害要因` に書いて親に判断させる。

## 中断と報告

- 実行中に新たな依存・競合・範囲外の問題を見つけた場合は、その作業を中断して親に報告する。
- 中断した場合は `状態` を `ブロック` とし、`次の行動` に親が取るべき判断を書く。
- 報告は必ず依頼と同じ `comm-agent/` のファイルに追記する。報告されない作業単位は未完了として扱う。
