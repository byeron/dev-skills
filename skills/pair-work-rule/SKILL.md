# pair-work-rule

1 つの作業に複数の worker を割り当てて進めるための基礎ルール。worker の定義、worker に与える要素、役割分担の型、worker 間の書き込み排他をここで定義する。

このドキュメントは**自己完結**している。worker の定義と分担の型、書き込み排他的な制約の定義はここだけに置く。

## worker の定義

- `worker` は 1 つの作業をペアワークで取り組む仮想的な作業者である。
- 1 つの作業単位には原則 2 人の worker があたる。
- worker は agent または subagent が務める。
- ユーザー（人間）は worker ではなく、判断を行う側である。

worker は役割を表すラベルであり、常時 2 人の独立した agent が必要なわけではない。1 人の agent が 2 役割を交互に担ってもよい。

## worker に与える 3 要素

| 要素 | 書くこと |
| --- | --- |
| `具体的な成果目標` | 2 人の worker が同じ状態を指せる成果。手順の列挙ではなく結果状態で書く |
| `共通の制約` | 双方が同じように守る条件。触らないファイル、前提とする入力、守る規約 |
| `補完的な責任` | 双方の責任が重ならず、合わせて 1 つの作業単位が完成する割り当て。片方だけでは完成せず、もう片方が欠落を補う形にする |

3 要素は worker 双方に同じ内容として共有する。片方にだけ伝えた制約は共通の制約ではない。

## 役割分担の型

| 作業の性質 | 片方の worker | もう片方の worker |
| --- | --- | --- |
| 調査タスク | 立案役。アイデアと候補を出す | 批判役。批判的な視点で議論し、実現性と欠落を指摘する |
| 実装タスク | 実装役。成果物を書く | レビュー役。成果を点検し、欠陥と不足を指摘する |

- タスクによって役割分担を柔軟に変えてよい。上の型は既定であり、型にない分担を禁止しない。
- 批判役・レビュー役は指摘を出す側であり、指摘された対象を自分で書き換えない。
- 批判役・レビュー役が点検する内容の詳細はこのドキュメントでは定義しない。

## 書き込み排他

- worker は同一ファイルへ重複編集を行うことを禁止する。
- 対象 issue への追記（成果目標、役割分担、相互確認の結果）は、1 作業単位ごとに決めた**記録担当**の worker だけが行う。もう一方の worker は issue へ書き込まない。
- 成果物への書き込みは、その成果物の担当 worker だけが行う。批判役・レビュー役は担当外のファイルへ書き込まない。読み取りのみとする。
- 担当が重なる場合は作業単位を分割して、書き込み対象が交差しないようにする。担当を分けられない作業単位は 2 人に分担しない。

## subagent との関係

- worker は subagent が務めてよい。worker の分担と subagent への委任は別の操作である。
- subagent へ分割してよいかの条件、委任の依頼と報告のフォーマット、委任に使う保存場所はこのドキュメントでは扱わない。
